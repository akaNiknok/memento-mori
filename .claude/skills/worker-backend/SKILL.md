# The Worker backend

Files this skill covers. Read the target file itself for detail; this table is why each one exists.

| File | Purpose |
| --- | --- |
| `worker/worker.js` | **The entry point.** `fetch` (assets fall through; `POST /tg`, `/login`, `/api`) + `scheduled` (cron dispatch). Holds **`ROUTES_READ` / `ROUTES_WRITE`** — the port of Router.gs's two tables. Both are exported so `test.js` can assert the naming rule. Auth on `/api`: the `mm_auth` cookie **or** `Authorization: Bearer <INGEST_TOKEN>` (the two GAS jobs); 401 is JSON, never a redirect — that's what lets `gs()` prompt and retry in place. `/tg` AWAITS the turn and answers after (v2.11.0) — a `waitUntil` task that outlives its allowance is CANCELLED, torn down without throwing, and the message is lost in silence; a pending request is not governed by that allowance. `scheduled` awaits for the same reason and dispatches on `event.cron`. Sets `env.APP_URL` from the request origin — that's the receipt's ✎ Edit details link. **`/tg` must stay `/tg`, not `/`:** a POST to `/` is answered 405 by the static-asset handler and never reaches the script (assets match before the Worker and only serve GET/HEAD). Verified with `wrangler dev`; undocumented either way, so don't re-derive it. |
| `worker/src/mcp.js` | **Read-only MCP at `POST /mcp`** for AI clients (2026-09-30). Stateless Streamable HTTP, JSON-RPC, tools only, no SSE/session. `initialize` echoes a version in `PROTOCOLS`, else the newest. Own credential `AI_READ_TOKEN` (unset = closed; localhost skips it like `/api`); the cookie and `INGEST_TOKEN` do NOT open it and it does not open `/api`. `TOOLS` is the whole surface: each wraps a `ROUTES_READ` handler and passes ONLY its declared args; `list_transactions` caps `limit` at 200. A prop with a `pattern` (month, date, from, to) is checked before the handler, and `listTransactions` throws on an unknown account/category (resolved case-insensitively): a bad filter must be an error, never an empty page an AI reads as zero spend. `get_categories` (`getCategories`) hands over the names and the descriptions that carry the filing conventions. **Kept off on purpose:** `getExportAll`, `listTable`, `getParse`. `test-api.js` guards all of it. A new tool = a new `TOOLS` entry over an existing read handler, never a write. |
| `worker/src/oauth.js` | **OAuth 2.1 for `/mcp`** (2026-09-30), for claude.ai web/phone, which cannot send a fixed header. Metadata (`/.well-known/oauth-protected-resource[/mcp]`, `/.well-known/oauth-authorization-server`), DCR `/register`, consent page `/authorize` (asks APP_PASS), `/token` (auth code + S256 PKCE, refresh). **Stateless, no library, no KV:** code/access/refresh are `b64u(json).b64u(HMAC)` with a signed `typ`, key derived from `AI_READ_TOKEN` — rotating it voids everything, unset = 404. **The real defence is `CALLBACKS`** (Claude's two callbacks, fixed in code): `/register` refuses others and `/authorize` shows an error rather than redirect. **Every token carries `auth` (consent time) forward and `/token` refuses past `CONSENT_TTL` (90 days)** — an old refresh token stays valid after a refresh (nothing is stored), so without it a stolen one renews forever. Codes are replayable for 2 min (PKCE makes that useless; `ponytail:` note has the KV upgrade). The consent page copies DESIGN.md tokens inline and is never framed. All routes are in `run_worker_first`. `test-api.js` runs the whole flow. |

Also the **admin grid** whitelist (`TABLES`) + `listTable`/`updateTableCell`/`insertTableRow`/`deleteTableRow`, and `getExportAll`. Those three are the ONLY table writes: the Tax screen uses them for `ledger` too (v3.2.0). |

| `worker/src/jobs.js` | The cron: `pricesJob` (IBKR Flex → `prices`) plus `runCron`, which wraps it and Telegrams the owner on failure. `runCron` also calls `api.js snapshotNetWorth` AFTER prices (so the snapshot uses fresh quotes); a snapshot failure is reported but non-fatal — prices, the critical job, already committed. **The daily-interest job was deleted in v2.0.1** — the bank's own figures never matched daily-balance×rate, so it posted a wrong number every night; `git show v2.0.0:worker/src/jobs.js` if it is ever wanted back. Its `interest-*` rows stay as history. |

| `worker/seed.sql` | **The local-dev fixture** (`npm run dev:seed`). Invented accounts, the real category taxonomy, and about 60 transactions over three months, modelled on the real database's shape: a USD contract salary into Wise, the Wise→IBKR growth funding, broker buys and one sale, a card that gets paid off, a refund as a negative expense, a Period override, an orphan ledger row for the ⚠ warning, and two `nw_snapshots` that agree with the seeded ledger (so the dashboard bridge's residual is near zero). Dates are RELATIVE (`date('now','start of month', mo||' months', …)`, clamped to today), so the app always opens on a populated month and the file never goes stale. It DELETEs before it inserts — re-runnable, and it replaces a `dev:pull`. `test-api.js` applies it to the real migrated schema, so a schema change that breaks it fails `npm test`. |

Done once (2026-09-25, MEMORY.md). Also holds **`[env.staging]`** (`develop`’s deploy target): no `name` key, because wrangler appends the env name itself. A contract guard in `test.js` holds all of it. |

## The database (`worker/migrations/0001_init.sql`)
Tables: `account_types · accounts · categories · transactions · budgets · recurring · ledger (+ ledger_view) · prices · nw_snapshots · email_quotes · seen_updates · meta`.
- **Money and quantities are INTEGER MICROS** (`*_u` = native units × 1e6). Exact integer sums, and the same column holds a fractional IBKR share quantity (a Shares row's amount IS a quantity, as in the sheet). **Convert at the API boundary only** (`toU`/`fromU`); a decimal mid-calculation is the drift the integers exist to prevent.
- **Dates are `yyyy-MM-dd` TEXT; month keys are `yyyy-MMM` (`2026-Aug`) everywhere, DB included** — the SPA, the Gemini prompt and Budgets all compare that exact shape.
- **Two generated columns, both STORED:** `transactions.month` = `COALESCE(period, <substr trick on date>)` (the Period override, replacing the ARRAYFORMULA and the `@`-text-format gotcha) and `amount_php_u` = `CAST(ROUND(amount_u * COALESCE(fx_rate,1)) AS INTEGER)`. **`ROUND` before `CAST`** — CAST alone truncates toward zero, which negative amounts expose immediately. **They use `substr`/`CAST` and NOT `strftime`:** SQLite registers the date/time functions as non-deterministic (they can read `'now'`) and a generated column may only call deterministic ones, so `strftime` fails at CREATE TABLE time. `test.js` asserts `monthOf()` and the substr expression agree.
- **`ledger_view`** does what the sheet's per-row formulas did: `LEFT JOIN transactions` on the **soft** `tx_id` (deliberately no FK — a deleted tx must render `⚠ transaction deleted`, not block the delete), deriving Date Received / Reporting Period / Wise Amount / Total Income / 8% Tax. `date_received`/`wise_amount_u` are literal fallbacks for legacy rows that were never linked. **`getLedger` reads ONE tax year** (`args.year`, default = the Manila year; it also returns `year` + the `years` present) — the table only grows and BIR files per year. A row with NO date is returned for EVERY year: that is a link to a deleted transaction, and a year filter must never be the reason a broken row goes quiet. **The ledger has NO write routes of its own** (v3.2.0): `ledger` is a `TABLES` entry, so `updateLedgerCell`/`appendLedgerRow`/`deleteLedgerRow` were a second copy of the admin grid and are deleted. `getLedger` ships `table`/`pk`/`edit` (header→column) so the client can drive the generic three. `TABLES.num` names the REAL-affinity columns, whose typed value is comma-stripped and cast in `coerceCell` — SQLite converts "56.5" but leaves "1,056.5" as TEXT, which then sums to 0.
- **`seen_updates` is a QUEUE, not just a dedup claim** (v2.12.0): `(update_id PK, at, payload, attempts, done)`. `seen()` claims an update AND stores it before the work; `settle()` closes the row and NULLs the payload; `unsee()` deletes it so Telegram's own redelivery can retry. A row left `done = 0` is a turn that died mid-flight — nothing throws when an invocation is cut off, so this row is the only trace — and `telegram.js drainUpdates()` re-runs it from the 2-minute cron. It calls `route()` and NOT `handleUpdate()` (which would see its own claim), re-stamps `at` BEFORE the work (no two drains on one row, and a failure backs off), gives up after `MAX_ATTEMPTS` with one ❌ message, and is safe against racing a merely-slow turn only because the row ids are idempotent. The sweep in `seen()` is scoped to `done = 1`: deleting a pending row is the silent loss this table exists to prevent.
- **`meta`** replaces Script Properties and is editable in the admin grid: `monthly_income_php`, `usd_php_fallback`, `owner_email`, `tg_last_ids`, `app_url` (written by `seen()` on every /tg turn, because a cron firing has no request origin and a rescued receipt would lose its ✎ Edit button). (`data_version` and `ledger_first_year` were dropped by `0006_drop_dead_meta.sql`.)
- **`prices`** is `(symbol, priced_at)` — history is free and is the audit trail the Sheet never had. `accounts.symbol` is the IBKR ticker (it used to live only inside the GOOGLEFINANCE formula). **Nothing fetches a price on the read path.**
- **`nw_snapshots`** is `(month PK, net_worth_u, assets_u, liabilities_u, shares_u, taken_at)` — the REAL monthly net worth the on-demand fold can't reconstruct (it always computes at today's FX/prices, and no historical FX is stored). Written by the daily cron (`api.js snapshotNetWorth`, upsert by month, so a month's last write is its close), stamping **yesterday's month** in Manila so the run on the 1st closes the previous month with its last day included. Signs match the API: **`liabilities_u` is NEGATIVE** (it sums the signed `netWorthPhp`, so `net_worth_u = assets_u + liabilities_u`; the SPA hero takes `Math.abs`), netWorth signed, shares⊂assets. A **negative receivable** counts as a liability, not a shrunken asset. `getDashboard` serves it as `netWorthHistory` (live month omitted — the chart uses live `netWorth` there); the SPA falls back to rolling cash flow backward for months with no snapshot yet. **History only accrues going forward** — pre-migration months stay estimates forever.
- **Balances are computed, not stored** (`db.js deltas()` + `shapeAccounts()`): native = `starting_balance_u` + Σ deltas, where **Income adds, Expense and Transfer subtract from the source, a transfer adds `to_amount_u` to the destination, and a LIABILITY account's delta is inverted** (it tracks an amount owed, so a charge raises it). PHP: PHP as-is; other currency × live FX; Shares × `prices` × the quote currency's FX. `availableCredit` = limit − balance for liabilities. The API fields keep their exact v1 names/signs: `balancePhp` (liabilities positive), `balanceNative`, `netWorthPhp` (signed), `availableCredit`, `isLiability`, `isShares`, `isInvestment`.


## How the backend works
**Contract:** the `/api` JSON contract is the v1 contract, deliberately unchanged — same `?action=` names, same argument names in the sheet's header casing (`Category`, `Amount`, `Amount (PHP)`), same `{status:'error'|'duplicate'}`. Freshness is an ETag, not a field in the body (see Caching). That's why `app.js` needed no changes outside the Admin screen; `test-api.js` is what holds it in place now.
**Routing:** GET `?action=` → `ROUTES_READ`, POST → `ROUTES_WRITE`. **Read/write is derived from the `get…`/`list…` handler-name prefix**, which is also how the SPA's `gs()` picks its method — one list, not two. `test.js` fails the build if a route is named against the rule (this is why `exportAll` from the plan is `getExportAll` here).
**Writes:** a write handler puts its statements in one `env.DB.batch()` — transactional, so `su_lock_()` is gone and there is no lock to take. **A write invalidates nothing and must not try**: `bumpStmt`/`data_version` were deleted in v2.9.0 (see Caching), and `test.js` fails the build if either name comes back into `api.js`.
**Caching — `worker.js readResponse`.** Every GET read is answered with an `ETag` over `JSON.stringify(body)`, and with **304, no body** when the caller's `If-None-Match` matches. This replaced one `meta.data_version` counter, which could only say "something changed" — so a 03:00 Telegram ingest re-downloaded every screen the phone had cached. Three consequences worth knowing:
- **A read payload must never carry a clock.** A per-request value makes every tag unique and the saving silently disappears. `test-api.js` calls every read route twice and fails if a tag moves. `getExportAll` is the deliberate exception (`exportedAt`); it is the backup puller's, not a cached screen's.
- **`getDashboard` moves on every write anyway**, because every month of it carries the live `netWorth`/`assets`/`liabilities` hero and the rolling cashflow. That is honest — the number really did change — so do not "fix" it by trimming the payload. The saving lives on Tax and the admin pages, whose past months and pages genuinely do not move.
- **`Cache-Control: no-store` stays.** The SPA holds the tag in its own persisted cache and sends `If-None-Match` itself, so the browser's HTTP cache is never in the path — one cache, and it is the one that survives a reload and works offline.
`meta.data_version` stayed in the table one release for rollback safety, then `0006` dropped it — the pattern for any future dead row.
**Idempotency:** `createTransaction`/`createTransfer` are `INSERT … ON CONFLICT(id) DO NOTHING` + `meta.changes===0` → `{status:'duplicate'}`. **The SPA's offline queue and Telegram's retry dedup both depend on that exact contract** — `test.js` guards all three parts of it.
**Auth:** cookie or bearer, both accepted on every action (there is one user). The **app shell is intentionally public** — no data, no secrets in it — which is also what keeps assets free and unmetered; only `/api`, `/login`, `/tg` burn invocations.
**Timezone:** Workers and D1 run in UTC. **Every "today"/quarter goes through `manilaToday()`.** A bare `new Date()` in a date-deciding path is a bug for eight hours out of every twenty-four; `new Date().toISOString()` as a *timestamp* is fine.
**FX:** `fx_rate` is a **static value stamped once at write time** — history never reprices. `resolveRate` gives a PHP or SHARES account no rate, whatever override the caller sent. `updateTransaction` re-stamps ONLY on an explicit ExchangeRate, a source-currency change, or a moved leg of a PHP-landing transfer (through `impliedRate`) — never because Account was sent, which the transfer form does on every save. A bulk reassign re-stamps only the rows whose currency changes. `createTransfer` refuses two currencies with no ToAmount (2026-09-23).
**Errors:** a handler throw is `{status:'error'}` at **200 only when it refused the payload** (`worker.js refused`: its own check, or a broken constraint); a D1 storage fault or a non-plain `Error` (a bug) is **500**. The SPA's offline queue drops a write only on the 200 — keep new failure modes on the right side of that line. Reads use `fxRate()`, which is a 6h KV entry, so a page load costs a network hop at most four times a day. `SHARES` short-circuits (it's a quantity, not a currency).
**Cron:** THREE triggers, dispatched by `jobs.js runScheduled(env, event.cron)`; `test.js` holds `wrangler.toml`'s list equal to `CRON_DAILY`/`CRON_DRAIN`, because a drifted string kills both jobs silently. `*/2 * * * *` runs `telegram.js drainUpdates` (below). `0 22 * * *` (06:00 Manila) does two jobs in order: IBKR prices, then the net-worth snapshot (upserts the current month, so daily runs keep it fresh and the last run of a month is its close). `0 1 * * *` (09:00, `CRON_RETRY`, 2026-09-27) runs the same pair ONLY if 06:00's prices failed: the 06:00 run sends no message on a price failure and writes it to `meta.prices_retry`; `retryCron` clears the key and re-runs, and only a second failure Telegrams ("failed twice", both reasons). If `metaSet` itself fails, 06:00 messages at once. **The free plan does not retry a failed cron**, so `runCron` catches and Telegrams the owner; a missed night is harmless (prices go one day staler; the snapshot fills on the next run).
**IBKR Flex:** `SendRequest` → ReferenceCode → `GetStatement`, polling while the code is in `FLEX_RETRY` (`flexRetryable`). **Poll every code IBKR ends with "Please try again shortly", not just 1019** — 1019-only cost a night of prices to one 1020 (2026-08-31). **1020 is in the set, and is also a STALE-REFERENCE code**: probing the live service shows 1020 is what IBKR answers to a request it cannot PARSE (a non-numeric token, a doubled `?`), while a wrong-but-well-formed token gets 1015 — so 1020 is not "transient" by itself. Our GetStatement shape is verified to parse, so a 1020 accuses the one non-static part, the reference code. `FLEX_STALE_REF` (1017, 1020) makes `pricesJob` ask for **one fresh reference code** instead of replaying a dead one; 1017 breaks out of the poll at once rather than being retried. Codes that need a human still fail fast and carry their repair in the message. The FIRST GetStatement waits too — IBKR allows one request per second AND **ten per minute** per token, which is easy to trip. The budget is paced to that ceiling: 6 tries at 6s plus a 2-try recovery = at most 10 calls in ~52s, asserted by a test. **`FLEX_PACE` is a parameter only so tests can skip the sleeps** — a contract guard holds `runCron` to the real pace. **`SendRequest` is on ndcdyn but the `<Url>` it returns is on gdcdyn** — always read the host from the reply. **A `User-Agent` header is required** or IBKR answers 403. Positions are parsed by regex (Workers has no XML parser) — the moment that needs real XPath, the query is asking for too much. **Quantities are logged, never written:** the ledger stays the source of truth for how many shares are held; IBKR only prices them.


## Backend conventions
- **A new UI-callable handler must be registered in `worker.js`** — `ROUTES_READ` (named `get…`/`list…`, GET) or `ROUTES_WRITE` (POST). Unregistered = "Unknown action".
- **A new write handler invalidates nothing** — the ETag does it. A new READ handler gets caching for free, as long as its payload is a pure function of the data.
- **Convert micros at the boundary, never mid-logic.** `ROUND` before `CAST` in any SQL that produces an integer amount.
- **`getDashboard` carries the whole budgets payload** (v2.14.0: `budgets` + `incomePhp` + `essentialsRewards`), because the Budgets SCREEN was merged into the Dashboard. `budgetsPayload` already ran there for the meters, so the extra fields cost no query. Named keys, never a spread: the payload has its own canonical `month` and `getDashboard` echoes back the month the caller asked for.
- **`getBudgets` carries `recurring`** (v2.9.0). The Budgets screen draws both and getRecurring is a handful of rows; two GETs meant two ETags and two round trips to learn nothing changed. `getRecurring` stays a route — getBootstrap and the admin grid use it.
- **A peso aggregate that can see a Transfer must carry `NOT_SHARES_SRC`** (db.js). On a share-priced account `amount_u` is a QUANTITY and a SELL leg (ticker→cash) gets no `fx_rate` — SHARES short-circuits `resolveRate` — so `amount_php_u` is a share count read as pesos. `budgetsPayload` is the one report that counts Transfers, so it is the one that carries it; `getDashboard`'s spend/flow and `getInvestments`' spendQ are Income/Expense-only. The bot's `querySummary` makes the same test in JS on the shaped `Currency`. A contract guard in `test.js` holds it.
- **`getInvestments` reads trades from ONE UNION ALL**, normalising buy (cash→ticker) and sell (ticker→cash) to `(cash, qty, side)`; a ticker→ticker move is excluded from both arms so nothing counts twice. **The quarterly PULSE then takes a narrower slice of those same rows** (`isPulseAcct` = share-priced AND an investment subtype): a leg into or out of a share-priced account filed under a cash-like subtype (IB01, subtype `EF`) is EF parking, which the runway card already counts, so the pulse skips it and the same peso is never measured twice. The cost basis is walked oldest-first over the FULL result — average-cost method, so a sale removes cost in proportion to the shares leaving and `avgCostNative` does not move on a sale. Two pools on purpose: `poolNative` is money actually paid, `poolPhp` the same legs at the rate stamped on the day (comparable to `valuePhp`, so it carries FX as well as market movement).
- **`getDashboard.bridge`** decomposes ΔNW into `savings` (income − expense) and `residual` (market, FX, timing — and unlogged spending). A closed month bridges snapshot→snapshot; the live month bridges the last snapshot→live net worth. Null when the previous month has no snapshot: history only accrues forward.
- **D1 has no interactive transaction** — `batch()` only, no `BEGIN` across an await. Bulk ops are one batch of statements.
- **`not_found_handling` must stay unset** in `wrangler.toml`: `single-page-application` would answer `/api` with `index.html`. Screen routing is on `?screen=` query params.
- **A text variation selector won't stop Telegram emoji-fying a glyph.** It renders every `Emoji=Yes` codepoint with its own emoji font and ignores `U+FE0E`, so `↩︎` shipped as ↩️. Where a text look is wanted, pick a glyph outside the emoji set (`↻ ✎ ⌕ ◈ ✦ › →`). Error marks `❌`/`⛔` are **deliberately** emoji — leave them. Guarded by `test.js`.
- **Debugging the bot:** `npm run tail` while you send a message. Setting the webhook again clears `last_error_*` and `pending_update_count`, so read `getWebhookInfo` *after* a fresh test message and *without* re-setting it first.
