# The SPA frontend

**The look is `DESIGN.md` (repo root) — read it before changing anything visible.** This skill is the mechanics; that file is the tokens, layout, components and motion. v3 shipped in v3.0.0; its phased plan is `git show v3.0.0~1:V3_PLAN.md`.

The theme head script and `applyTheme` swap the favicon + apple-touch-icon hrefs to the `-dark` files (iOS captures the icon at Add to Home Screen); the manifest stays light. **The art is the `MARK` path inside `icons.js` — a copy of `brand/mm-symbol-small.svg`, the small-size cut, because icon-180 is also the favicon.** The PNGs are generated — never hand-edit them: `npm run icons` renders the SVG with whatever Chrome/Edge is installed (`--headless --screenshot`). 180 = `apple-touch-icon` + favicon, 512 = manifest; both `purpose:"any maskable"`, mark (58 of 96) inside Android's 80% safe circle. **Deliberately square with no rounded corners** — iOS rounds the apple-touch-icon and Android masks the maskable one, so baked-in corners double-round. ## Web App frontend
**Serving:** the Worker serves `worker/public/` as static assets, same origin as `/api`. No bundler, no build step.
**Data path:** `gs(fn, arg)` → `/api`. Reads GET, writes POST, chosen from the handler-name prefix. `gs()` rejects on `{status:'error'}`, and on a **401** asks for the passphrase once (`unlock()` → `POST /login`) and retries. `unlock()` renders a **real `<form>` in the app's own modal — never `window.prompt`**: prompt shows the passphrase in clear text, no password manager can fill it, and its iOS field autocapitalises. `type=password` + `autocomplete="current-password"` (plus a readonly username field so the saved entry has a name) is what gets iOS AutoFill. Concurrent 401s share one dialog (`_unlocking`); a wrong passphrase re-asks in place; cancelling must settle the promise (`closeModal.onClose`) or every later 401 awaits a dead one.
**Screens:** Summary (key `dashboard`, v3 Phase 2: the `.sum` tile grid — net worth with sparkline and bridge chip, Left to spend (the Essentials+Rewards roll-up plus every budget as a segment row, off `getDashboard`'s budgets payload), Financially free in, Emergency runway (read from `cachedCall('investments')`, the Accounts payload, whose `runway.parts` are the tooltip rows), the history tile (`historyCharts`: net-worth stack and cash-flow bars on ONE band per month, one inspect line and tooltip through both, 6M/1Y/2Y = `S.cfMonths`), spending by category, recent. Spans live in `app.css`; the charts mount at rAF at the host's width. The Budgets screen was merged into it in v2.14.0 and `getBudgets` stays a route for an old cached `app.js`; the Recurring card went to Accounts and reads `S.boot.recurring`) · Activity (key `transactions`, v3 Phase 3: ONE filter object `S.tx.filters` (keys `TX_KEYS`) drawn as tokens in a search field; `parseTokens` is the pure grammar behind the field's suggestions (tested in test.js). `month:''` means all months, and an unset month defaults to the Summary's. Smart lists = `builtinLists()` in code + `S.boot.smartLists` (`setSmartLists`, meta `smart_lists`). From 1200px (`txWide()`, a matchMedia listener re-renders on the crossing): filter pane + `txTableRow` table; below: `txRow` grouped by day, the Filters sheet (`openModal(node,{sheet:true})`, a bottom sheet under 768px) and touch-only swipe (`swipeWrap`). Select mode (`S.tx.edit`) = checkboxes + inline single-field edit + the sticky floating bulk bar; the category/account/date links add tokens only when browsing. The result line's net is `listTransactions.net`, the WHOLE filtered set, not the page) · Accounts (v3 Phase 5: totals (Assets / Liabilities / Net worth, the `netWorthTotals` split, so a negative receivable is a liability), then grouped lists — cash and banks (interest line from `interestRate`, a fraction), credit (a limit meter; `availableCredit <= 0` = "Limit reached" in `--warn`), a Holdings row that jumps to Investments, receivables, the `loadDebts` itemisation and recurring (off `S.boot.recurring`). A phone puts each group's label above its card; from 768px a group is a tile in two columns) · Investments (key `investments`, v3 Phase 5, in the More sheet on a phone: Invested with gain, the quarterly pulse, allocation (with the strategy targets) and the holdings table, all from `cachedCall('investments')` — the same key Summary's runway reads. A ticker's colour is `invColors`: its account colour, else a token slot by name, the same on every tile. The pulse counts GROWTH tickers only — `pulse.excluded` names the EF parks it skips — and draws its bar from BUYS only, a sell being a red detail line and a dashed empty track, because the bar measures money going in. Positions carry `price`/`priceCurrency`/`pricedAt`; the subtitle is the newest `pricedAt`) · Swap (key `exchange`, v3 Phase 6: inputs as a grouped list, the hero result with the range bar; `swapCalc` is the pure maths, tested; **Record this swap** opens `openTransferModal` filled by `swapDraft`, so the implied-rate rule stamps the fair rate) · Tax (v3 Phase 6: quarter tiles from `taxQuarters`, pure and tested, the unlinked-salary banner, then the ledger table) · **Admin** (v3 Phase 6: the table picker is a segmented control; a locked column carries the lock icon; under the grid, the iPhone balance widget picker: chips off `S.boot.accounts`, saved on each tap through `setWidgetAccounts`, max 3). Activity and Admin share `pagerEl`. Dates are day first everywhere (`fmtDate`, `shortDate`). Deep links: `?screen=<name>` wins over the stored last screen; `?tx=<ID>` opens that transaction's edit modal (the Telegram receipt's target) via `openTxById`. Labels are Summary and Activity; the keys stay `dashboard` and `transactions`.
**Admin screen (new in v2.0.0):** a generic CRUD grid over the server-side whitelist. **The Sheet used to be the admin UI** — adding a category, retiring an account, fixing a budget target were all "open the tab and edit the cell" — so this replaces exactly that. It renders whatever `listTable` tells it: the server owns which tables exist, which columns are editable (`edit`), which are settable on insert (`add` — a natural PK appears there and not in `edit`, because renaming one under a live FK is data loss, not a cell edit) and which are micros (`money`, converted both ways at the boundary). **`transactions` is read + delete only** — it has real handlers with validation and FX stamping, and the grid must not be a way around them. **`nw_snapshots` is fully read-only** (`edit:[]` + `nodelete:true`): cron-owned history the grid must not hole; `listTable` reports `deletable:false` and the client hides the delete button. No SQL console, deliberately: anything this can't express is `wrangler d1 execute`.
**Tax screen:** `getLedger` returns `rows` keyed by the **sheet's old header names** (`__row` is now the ledger row id — an opaque handle, so the client is unchanged), `cols` in `LEDGER_COL_ORDER`, and `derived` (rendered read-only). **It WRITES through the Admin grid's three routes** (v3.2.0): `ledger` was always a `TABLES` entry, so `updateLedgerCell`/`appendLedgerRow`/`deleteLedgerRow` were a second copy of `updateTableCell`/`insertTableRow`/`deleteTableRow` and are deleted. `getLedger` also ships `table`/`pk`/`edit` — `edit` is the header→db-column map, the one thing the client cannot derive — and `renderTax` packs all of it into `ctx`. A saved cell **redraws the whole screen**, because a BSP rate moves the derived columns with it and the payload is one ETag'd read of a table that holds one row per payslip. The shared pieces are `cellEdit`/`gridAddRow`/`gridDeleteRow`, used by both screens. `Filed?` is a native `<select>` of BIR quarters (`quarterSelect`), deliberately not the fuzzy combobox. The BSP rate column's ⓘ links out to the BSP daily rate page (`spec.link`; a pointer can cross into the popover) — **`BSP Reference Rate` is deliberately not the app's FX**: BIR wants the central bank's reference rate on the date of receipt, which the app has no feed for, so it stays hand-typed per payslip. The unlinked-salary banner lists `unlinked`, and **Add to ledger** appends one row per salary writing *only* `Transaction ID`; everything else derives. `LEDGER_LABEL` holds the short column names the table shows.
**Non-obvious UI constraints:** chart series tokens are `--chart-in` / `--chart-out` (v3 renamed `--chart-income`/`--chart-spend`; values per theme in DESIGN.md) — revalidate 3:1 against `--card` in both themes if changed. **Income-green vs spending-red is a red/green CVD-confusable pair**, mitigated by position (income bar left, spend right), the legend, and the tooltip — colour is never the only channel. The net-worth line is `--accent` (blue), distinct from both. Form/filter pickers are a custom **fuzzy combobox** (`comboEl`/`fuzzyScore`), deliberately not `<select>`. The add field's **full form adds transfers too** — `typeToggleEl` swaps `openTxModal`⇄`openTransferModal` in place, carrying Date/Account(→From)/Amount/Description but **not** Category (disjoint sets). **Desktop ≥1200px is two columns (`.cols` on the screen root, `columns:2` in `app.css`), not a grid** — a grid row is as tall as its tallest card, so one long account list left a half-screen void; multicol balances instead. A card that needs the full width carries `wide` (`column-span:all`): both dashboard charts, the KPI row, and `.hero-row` — the wrapper that pairs the FI and net-worth heroes into one equal-height row (`display:contents` below 1200px, so the phone stack is untouched; without it the two land in different columns at their own heights and leave a ragged gap under the shorter one). **`wide` is set in JS, never by `:has(svg)`** — a chart is appended at rAF, so the column count would change after the chart measured its host.
**No web fonts:** the system stack (`--font`, DESIGN.md "Typography"), so text costs nothing and works offline. Do not add a font file, an `@font-face`, a font preload or a font entry in `sw.js` `SHELL`.
**Shell (v3):** one `<nav id="nav">` in `index.html` is three layouts by width in `app.css`: a tab bar under 768px (Summary, Activity, Accounts, More — the More sheet holds Swap/Tax/Admin plus the sync state and theme button), a 76px icon rail at 768–1199px, a 240px sidebar from 1200px. The add field (`.addbar`, `#addInput`) is docked above the tab bar on a phone and a header row from 768px; `wireShell()` wires it, the theme and the sync state. **Quick add (v3 Phase 4):** `parseAdd` (pure, tested) is the instant pass — amount, account (exact name or 3+ letter prefix; the LAST one named wins, and two make a transfer only with "to" between them), category from `S.boot.descCategory`. `qaDraft()` layers local → Gemini (`getParse`, **on Return only** — `qaSave` is its one caller, and `QA.aiFor` keeps it to once per text; there is deliberately no typing-pause fire, because the AI answer is dropped the moment the text changes, so a pause fired a call per pause against a ~250/day free tier) → the owner's chip picks (`QA.over`). It saves through `commitTx`, so it is optimistic and queues offline; a partial draft opens the full form filled — the typed text is never dropped. The chips reuse `openPicker`, which opens a lone picker page when the editor is closed. On a phone the open panel makes `.addbar` a full-screen page (`body.qa-on`), and `qaFit` sizes it to the VISIBLE viewport (`visualViewport.offsetTop`/`height`) so the field sits right on the keyboard. **Theme:** `mm.theme` = `light`/`dark`/absent (Auto); the head script in `index.html` sets `data-theme` and the `theme-color` meta before first paint, `applyTheme()` does the same at run time — keep the two in step. **Sync state** (`syncText`/`syncUI`): offline is what `gs()` last saw (`netSeen`), never `navigator.onLine`; the count is `queue().length`. **Icons:** the `<symbol>` sprite in `index.html`; `icon('name')` returns the markup. **Both overlays are real `<dialog>`s** (v3.2.0): `#modalRoot` in `index.html` and `ED.root` built by `edRoot()`, opened with `showModal()`. The top layer gives the focus trap, Escape (`cancel`), `::backdrop`, focus restore and STACKING — `trapFocus` and its walk up the DOM inerting siblings at each level are gone, and so are the `.modal-backdrop`/`.ed-backdrop` divs and the document-level Escape listener. Rules that follow from it: **the element IS the full-viewport host and the card is its child**, so a backdrop click is `e.target === root`; **`cancel` is always `preventDefault`ed** and the close routed through `closeModal`/`popPage`, or the UA closes behind the bookkeeping's back; **`.open`, never `.hidden`** to test whether one is up; **a child that wants Escape for itself calls `preventDefault`** (`comboEl` does, while its list is open) because `stopPropagation` no longer suppresses a close request; **the editor closes with the animation running and `close()` on the timeout**, since `close()` leaves the top layer at once and there would be nothing left to animate (so `openEditor` inside that window must not `showModal()` again); **the editor's card is `ED.card`, never `lastChild`** — `toastRoot()` below parks `#toastRoot` inside the open dialog, where it becomes the last child (test.js guards this). A new or edited row passes `draftError` before `commitTx`: offline, anything the server would refuse is queued and then dropped at sync. `#toastRoot` is still a sibling of `#app`, and `toastRoot()` re-parents it into whichever dialog is open — a modal dialog makes the rest of the document inert, live regions included, so an error raised from a form would otherwise never be announced. The More sheet (`#sheetRoot`) is deliberately NOT a dialog: it is a nav menu, it traps nothing. **A crash net** (`crash`, on `error` and `unhandledrejection`) toasts anything thrown outside a promise chain, and falls back to `showErr`'s Retry when nothing usable is on screen. **`tip(spec)`** returns the ⓘ button for a derived figure (spec = `{title,text,rows:[[label,value,bold]],note}`, or a function returning it so the rows read live values); `tipHTML` is the pure part and is tested.
**Perf:** payloads are cached client-side (`S.cache` = `key → {data, etag, at}`, persisted to localStorage) and revalidated through `cachedCall`. **The revalidation is an ETag, not a version (v2.9.0):** the loader is `function(etag)`, `gs()` sends it as `If-None-Match`, and a 304 comes back as `{__304:true}` — keep the paint, restamp `at`. A 200 carries `__etag`, which `cachedCall` lifts off before storing. The old `meta.data_version` counter moved on EVERY write, so a Telegram ingest the owner never saw re-downloaded every cached screen; a tag over the payload's own bytes is the only thing that can see the month-, year- and page-scoped keys. **`S.bootEtag` does the same for `getBootstrap`** — the biggest single payload, now a 304 on a relaunch that changed nothing. The dashboard key is month-scoped, so `monthPickerEl` must **not** wipe `S.cache` on change. Transactions add/delete are optimistic. **`LS_SCHEMA` is a cached-payload shape stamp — bump it whenever a payload's shape changes** (10 = the Dashboard carrying the budgets payload). **There is no push:** a screen left open never updates itself; the app revalidates on navigation AND on RESUME (`onResume`, wired to `visibilitychange` and to a `pageshow` out of the bfcache). iOS suspends a backgrounded PWA and restores it in place, so the app switcher would otherwise show days-old figures under a green "Synced" dot. The threshold is `REVAL_TTL`, so a quick flip to the Telegram bot and back still repaints at once while Data Saver keeps its 60 s radio protection; the repaint is SKIPPED (the stamps still clear) while the editor, a modal or any field has focus, or a resume would throw away a half-typed transaction. **`dropCache()` after a write keeps the TAGS** and only clears the freshness stamps — the screens the write did not move then answer 304 instead of refetching; `refresh()` is the one that goes properly cold. **Data Saver (`navigator.connection.saveData`) buys two things:** `REVAL_TTL` becomes 60s instead of 3s, and `sw.js` serves a cached shell file WITHOUT the background revalidation — on a cell connection the radio wake-up costs more than the 304 does. Refresh clears the cache and the whole `caches` store, so it stays the escape hatch for both. **The Dashboard is the one screen that cannot 304 after a write** — every month of it carries the live net-worth hero, so the bytes really do change. **One page, never a whole table:** the Admin grid pages at `ADMIN_PAGE` (50) with `listTable`'s `offset`; its ↓ CSV button calls `adminFetchAll` so the FILE is still the whole table (the old `limit:500` grid silently truncated it). The Tax screen asks `getLedger` for one year and picks it with `ledgerYearSelect`.
**App-shell scrolling (v1.6.5), don't undo it:** `html,body{overflow:hidden}` and `#app` is exactly one viewport tall, so **`.main` is the only scroller** — the document must never scroll, or iOS rubber-band overscroll drags the topbar/nav off the screen edges. Height comes from **`--app-h`, set in JS in `index.html` before first paint**, because iOS standalone + `black-translucent` + `viewport-fit=cover` reports `innerHeight` as **screen minus the top inset** (797 vs 844 on a 390×844 phone) while painting from y=0 — only `screen.height` sees it, and the shim keys on `screen.height === innerHeight + insetTop` so every other platform falls through. The nav's ~34px bottom padding **is the home-indicator clearance, not a bug**. Changing `apple-mobile-web-app-status-bar-style` is not a fix path: **iOS reads those metas at Add-to-Home-Screen time.**
**Offline (v1.6.1):** three layers. **Shell** — `sw.js` caches `/`, `/app.css`, `/app.js`, `/manifest.json` network-first with a 3 s timeout, cache as the fallback (v3; cache-first put every deploy on the second launch) (`ignoreSearch`, so a deep link matches the cached `/`); it deliberately **never caches `/api`**. **Reads** — the persisted `S.cache` (a failed revalidation keeps the stale paint). **Writes** — a `localStorage` queue (`mm.queue`) flushed on `online`, at launch, and by Refresh. **Only `createTransaction`/`createTransfer` are queued** (`QUEUEABLE`) because only they are idempotent on a client-supplied ID — `gs()` stamps a `ui-<ts>-<rand>` ID *before* the first attempt for exactly that reason. Everything else refuses with an offline message. Pending rows are derived from the queue (`rebuildPending`). A flush **discards a queued write only when the server explicitly rejects the payload** (`_server`, set ONLY on an HTTP 200 error — the Worker answers a D1 fault or a bug with 500 since 2026-09-23); offline, a lapsed cookie, a cancelled prompt or a 5xx all keep it and stop the run — dropping money because the cookie lapsed would be the worst bug in here. `flushQueue._busy` is what stops `gs()` re-queueing during a flush. **`queueSet` THROWS on a full quota** rather than swallowing it: it evicts `LS_CACHE` (disposable by definition, and the only thing big enough to fill the quota) and retries, and if that fails too the error reaches `commitTx`, which reopens the editor with the typed payload. A swallowed quota error was the same "dropping money" bug through another door — the app toasted "Saved offline" over a transaction it never stored. **`gs()` arms `AbortSignal.timeout(GS_TIMEOUT)`** because a dying connection leaves `fetch` hanging instead of rejecting, and the whole story above runs off that rejection; the abort is read as offline, which is right, since the replay carries the same client-supplied ID.
